# 学习 Kafka：概念、使用场景与幂等性保障

本卡目标是完成 Kafka 学习闭环：理解核心概念、知道为什么要用 Kafka、掌握基础使用方式，并能说明高并发下消息幂等性的落地方案。

---

## 一、Context（背景）

### 1. Feature 背景

随着系统并发增长，业务需要通过异步解耦、削峰填谷、可回放数据流来提升稳定性与吞吐。Kafka 是主流消息中间件，理解其机制是后端工程能力的重要基础。

### 2. 本卡背景

本卡是自学任务，不是功能开发卡。重点是建立“概念理解 + 配置认知 + 可靠性设计”三层知识结构，尤其要搞清楚高并发下如何避免重复消费导致的数据写脏问题。

---

## 二、In Scope / Out of Scope（边界）

### In Scope（做什么）

- 学习 Kafka 核心概念：Broker、Topic、Partition、Replica、ISR、Offset、Consumer Group
- 理解为什么使用 Kafka：解耦、削峰、异步化、吞吐扩展、可回放
- 学习 Kafka 基础使用方式：
  - Producer 发送消息
  - Consumer 消费消息
  - 消费者组与分区分配关系
  - Offset 提交策略（自动/手动）
- 学习并总结高并发下 Kafka 幂等性保障方案（生产端 + 消费端）
- 产出学习笔记文档并沉淀到仓库（`doc/learn/kafka.md`）

### Out of Scope（不做什么）

- 不要求本卡内搭建完整 Kafka 集群（KRaft/ZK）
- 不要求本卡内完成生产级压测报告
- 不要求接入业务系统做端到端联调
- 不扩展到 Kafka Streams/Flink 实时计算专题

## 四、Tech 实现参考

### 推荐学习顺序

1. 概念层：Broker / Topic / Partition / Replica / ISR / Offset / Group
2. 机制层：顺序写、Page Cache、零拷贝、分区并行
3. 可靠性层：`acks=all`、`min.insync.replicas`、手动提交 Offset
4. 幂等层：Producer 幂等 + Consumer 业务幂等双保险

### 幂等性关键配置与策略

- Producer：
  - `enable.idempotence=true`
  - `acks=all`
  - 合理设置 `retries`
- Broker：
  - `replication.factor>=3`
  - `min.insync.replicas>=2`
  - `unclean.leader.election.enable=false`
- Consumer（业务层）：
  - 唯一索引防重复写入
  - Redis `SETNX` 防重占位
  - 状态机前置条件更新（如 `... WHERE status='PENDING'`）
